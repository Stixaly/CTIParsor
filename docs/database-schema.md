# Database schema

The tables of the job store and the detection-rule store.

PostgreSQL only (ADR-0045, ADR-0053) — `DATABASE_URL` is mandatory, and both
the job-store tables (jobs, job_baselines, entities, relationships, review
journal, progress, worker_heartbeats, policy, thresholds, overrides, figures,
caches), the accounts and audit tables (users, sessions, api_tokens,
login_failures, oidc_logins, audit_events; ADR-0097) and the detection-rule
tables below live in the same database. `job_baselines` is the STIX
bundle an `enrich` job starts from (ADR-0090). Shown here close to plain SQL for
readability; the actual DDL uses `GENERATED BY DEFAULT AS IDENTITY` where
this shows `AUTOINCREMENT` and `DOUBLE PRECISION` where this shows `REAL` —
same names, same columns otherwise.

**The schema is versioned (ADR-0077).** `api/migrations/` holds one module per
version since the first PostgreSQL job store; `schema_migrations` records, per
database, every version it has (`applied`, or `recognised` for a database
created before the history was versioned), with a checksum, the time and the
code revision. The API, every worker and `bootstrap` bring the database to the
code's version at start (`api.migrate`); `python -m api.migrate status` says
where a database is. How to add a version: docs/development.md, "Database
migrations".

```sql
CREATE TABLE jobs (
    id              TEXT PRIMARY KEY,
    original_filename TEXT NOT NULL,
    status          TEXT NOT NULL DEFAULT 'uploaded',
    report_text     TEXT,           -- refanged extracted text (stored once)
    bundle_json     TEXT,           -- serialised STIX bundle
    llm_result_json TEXT,           -- LLM result snapshot for finalize
    resolved_types_json TEXT,       -- Stage 2's type-conflict losers, for the finalize ledger (#397); NULL before version 15
    tlp_level       TEXT,           -- per-job TLP marking (clear|green|amber|amber+strict|red, ADR-0073)
    pap_level       TEXT,           -- per-job PAP statement marking
    run_config_json TEXT,           -- run-config snapshot (ADR-0024): a bundle
                                    -- stays explainable after the policy changes.
                                    -- It describes the RUN; a finalize's own build
                                    -- is bundle_build_json (ADR-0086)
    worker_id       TEXT,           -- which worker claimed this job (ADR-0046)
    heartbeat_at    TEXT,           -- last time that worker reported alive;
                                    -- stale past WORKER_LEASE_TIMEOUT_S -> requeued
    bundle_ledger_json TEXT,        -- what Stage 4 did with each row (ADR-0061):
                                    -- the Graph page's bundle view reads it
    bundle_validation TEXT,         -- Stage 5's verdict on bundle_json (ADR-0084):
                                    -- validated | unverified | invalid.  Written in
                                    -- the same UPDATE as the bundle.  NULL = built
                                    -- before v11, or Stage 5 did not run: unknown,
                                    -- served as before.  invalid is not served (409)
                                    -- and never completes the job
    bundle_validation_errors TEXT,  -- JSON list: the first 20 error messages, 500
                                    -- characters each; NULL when there are none
    review_revision BIGINT NOT NULL DEFAULT 0,
                                    -- ADR-0086: the number of writes to this job's
                                    -- entities and relationships rows.  Bumped by the
                                    -- triggers below, in the transaction of each write
    bundle_review_revision BIGINT,  -- the review_revision bundle_json was read at.
                                    -- A finalize stores its build only if this is NULL
                                    -- or <= the revision the build read.  A run stores
                                    -- its bundle with the job's current review_revision,
                                    -- guarded by worker_id (ADR-0086).  NULL = built
                                    -- before v12, or by a writer with no snapshot
                                    -- (none left since #441): any build may replace it
    bundle_build_json TEXT,         -- what built bundle_json: kind (run | finalize |
                                    -- quick), built_at, git_rev, policy, env (the
                                    -- allow-list), manifest, and baseline_sha256 when the
                                    -- bundle was merged with a baseline (ADR-0090).  A
                                    -- finalize whose record cannot be built keeps only
                                    -- kind, built_at and error (ADR-0086).  Written in
                                    -- the same UPDATE as the bundle.  NULL = built
                                    -- before v12: run_config_json describes it
    pipeline_mode   TEXT NOT NULL DEFAULT 'full',
                                    -- ADR-0090: 'full' (the report alone) | 'enrich'
                                    -- (the report and a STIX 2.1 bundle the analyst
                                    -- holds, stored in job_baselines)
    attempts        INTEGER NOT NULL DEFAULT 0,
                                    -- ADR-0097 item 20: the claims of this job by a
                                    -- queue loop; requeue_orphans fails the job once
                                    -- it reaches JOB_MAX_ATTEMPTS (default 3)
    imported_by     TEXT,           -- ADR-0097 item 15: the id of the user who
                                    -- imported the report; NULL for a row stored
                                    -- before version 18, which only an admin deletes
    activity_at     TEXT,           -- #723: the last human decision or edit on the
                                    -- report (same transaction as the write); NULL
                                    -- when none is known. The retention sweep keeps
                                    -- a report while this or updated_at is recent
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

-- The STIX bundle an `enrich` job starts from (ADR-0090): at most one row per job,
-- deleted with it (the foreign key cascades, and `_delete_job` in api/routes/jobs.py
-- also deletes it explicitly, like the other children).  A job the full queue refuses
-- is set to `failed` and its row deleted (`run_pipeline_async`).  Kept out of `jobs`
-- so that no `SELECT * FROM jobs` drags up to 20 MB with it.
CREATE TABLE job_baselines (
    job_id      TEXT PRIMARY KEY REFERENCES jobs(id) ON DELETE CASCADE,
    sha256      TEXT NOT NULL,      -- of the bytes received
    size_bytes  INTEGER NOT NULL,
    report_id   TEXT,               -- the Report of the bundle the job enriches; NULL
                                    -- when the bundle holds none
    bundle_json TEXT NOT NULL,      -- the bundle as received (UTF-8), never rewritten
    index_json  TEXT NOT NULL,      -- BaselineIndex: ids and matching keys, not objects
    intake_json TEXT NOT NULL,      -- Intake, with its field names: sha256, bundle_id,
                                    -- counts, excluded (objects left out and why),
                                    -- warnings, reports, scope_report_id,
                                    -- needs_report_choice, min_tlp, min_pap.  Both JSON
                                    -- texts are ASCII (a NUL or a lone surrogate is an
                                    -- escape)
    validated   INTEGER NOT NULL DEFAULT 0,
                                    -- 1 once the worker has run the intake again with the
                                    -- JSON schemas, which the request does not (index_json
                                    -- and intake_json are then the worker's)
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);

CREATE TABLE entities (
    id          TEXT PRIMARY KEY,
    job_id      TEXT NOT NULL,
    value       TEXT NOT NULL,
    entity_type TEXT NOT NULL,
    context     TEXT DEFAULT '',
    confidence  REAL DEFAULT 1.0,
    mitre_id    TEXT,
    accepted    INTEGER,            -- NULL=pending  1=accepted  0=rejected
    source      TEXT DEFAULT 'auto' -- ioc | gazetteer | semantic | cyner |
                                    -- gliner | llm | manual | report_lexicon
                                    -- (report_lexicon: rows of the re-scan removed
                                    -- on 2026-10-17; nothing writes it now) |
                                    -- baseline_stix (ADR-0090: a row the analyst's
                                    -- STIX bundle adds; a matched row keeps the
                                    -- source of its extraction)
    -- Entity evidence (ADR-0028), kept apart from `context`: over 280 stored
    -- TTPs only 36.8% of `context` is findable in the report, against 79.4%
    -- for verbatim quotes.  Both offsets are stored because normalisation
    -- folds curly quotes and space runs, so the quote and the span differ in
    -- LENGTH — 68 of 313 (21.7%) did not survive text[start:start+len(text)].
    evidence_text TEXT,
    evidence_label TEXT,
    evidence_start INTEGER,
    evidence_end INTEGER,
    -- Who decided `accepted` (ADR-0058), NULL while nobody has:
    decision_origin TEXT,           -- human | human_bulk | auto_policy | default |
                                    -- baseline_stix (ADR-0090; written by the server,
                                    -- not a human origin) |
                                    -- propagated (the removed re-scan: older rows
                                    -- only) | legacy (decided before the column)
    decided_at     TEXT,
    policy_version TEXT,            -- the auto-accept policy that decided, if any
    control_sample INTEGER NOT NULL DEFAULT 0, -- 1 = auto-accept left it pending
                                    -- on purpose, to measure its own accuracy
    held_reason    TEXT,            -- ADR-0082: why the pipeline held this row back
                                    -- (a technique Stage 3f could not decide); a
                                    -- pending row with a reason ships only once accepted
    enrichment_status TEXT,         -- ADR-0090, NULL in full mode and for a row added by
                                    -- hand: new (extracted, not in the baseline) |
                                    -- matched (extracted, already in it: accepted at
                                    -- once, origin baseline_stix) | baseline_in_text
                                    -- (imported, its text is in the report: its span is
                                    -- kept as evidence, unless lower-casing changes the
                                    -- report's length) | baseline_only (imported, its text
                                    -- is not in the report).  Set by Stage 3r
                                    -- (pipeline/baseline_stix.py).  An imported row is
                                    -- written accepted, origin baseline_stix.  It can be
                                    -- accepted or rejected, but its type, value and ATT&CK
                                    -- id are not edited (409), and it is not deleted (409)
    baseline_stix_id TEXT           -- the id of the baseline object the row is or matches
);

CREATE TABLE relationships (
    id                TEXT PRIMARY KEY,
    job_id            TEXT NOT NULL,
    source_value      TEXT NOT NULL,
    relationship_type TEXT NOT NULL,
    target_value      TEXT NOT NULL,
    confidence        REAL DEFAULT 0.8,
    accepted          INTEGER DEFAULT 1,  -- NULL=pending  1=accepted  0=rejected
    evidence_text     TEXT,               -- verbatim supporting quote
    evidence_label    TEXT DEFAULT 'reported', -- observed|reported|assessed|inferred|gap
    times_json        TEXT,               -- every date the source attaches to the
                                          -- relationship, as JSON (ADR-0063)
    start_time        TEXT,               -- legacy: written by nothing since ADR-0063,
    stop_time         TEXT,               -- read as dates of unknown precision
    decision_origin   TEXT,               -- as on entities (ADR-0058), incl. baseline_stix
                                          -- (ADR-0090): a matched or an imported row
    decided_at        TEXT,
    policy_version    TEXT,
    held_reason       TEXT,               -- ADR-0082: why Stage 3d held this claim back;
                                          -- stored pending, ships only once accepted
    enrichment_status TEXT,               -- as on entities (ADR-0090).  An imported row is
                                          -- baseline_in_text when both its ends are matched
                                          -- or found in the report text, baseline_only
                                          -- otherwise.  Written accepted, origin baseline_stix:
                                          -- its endpoints, verb and dates are not edited (409),
                                          -- and it is not deleted (409)
    baseline_stix_id  TEXT
);

-- The revision of a job's review (ADR-0086).  A row-level AFTER trigger on
-- entities and on relationships adds 1 to jobs.review_revision, in the
-- transaction of the write itself: no route, worker step or script has to
-- remember to.  A row moved to another job (UPDATE of job_id) bumps both jobs.
-- The UPDATE names the schema of the table that fired the trigger, since the
-- tests, and any deployment that sets search_path, have their own `jobs`.
CREATE FUNCTION bump_review_revision() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE
    jobs_touched text[];
BEGIN
    IF TG_OP = 'INSERT' THEN
        jobs_touched := ARRAY[NEW.job_id];
    ELSIF TG_OP = 'DELETE' THEN
        jobs_touched := ARRAY[OLD.job_id];
    ELSE
        jobs_touched := ARRAY[NEW.job_id, OLD.job_id];
    END IF;
    EXECUTE format('UPDATE %I.jobs SET review_revision = review_revision + 1 WHERE id = ANY($1)',
                   TG_TABLE_SCHEMA) USING jobs_touched;
    RETURN NULL;
END
$$;

CREATE TRIGGER entities_review_revision AFTER INSERT OR UPDATE OR DELETE ON entities
    FOR EACH ROW EXECUTE FUNCTION bump_review_revision();
CREATE TRIGGER relationships_review_revision AFTER INSERT OR UPDATE OR DELETE ON relationships
    FOR EACH ROW EXECUTE FUNCTION bump_review_revision();
-- Cost: about 0.1 ms per row written.  Policy, data and code changes do not
-- bump it: they are not decisions.  A statement-level trigger was measured
-- slower on the run's executemany write and not adopted (ADR-0086, amendment
-- of 2026-10-18).

-- The review journal (ADR-0058): one row per change of `accepted`, only ever
-- inserted into.  No foreign key to jobs, on purpose: deleting a report must
-- not erase who decided what on it.  Rows hold ids, origins and times, not
-- report content.  Threshold calibration and the auto-accept audit read it.
CREATE TABLE review_decisions (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    job_id         TEXT NOT NULL,
    target_kind    TEXT NOT NULL,     -- entity | relationship
    target_id      TEXT NOT NULL,
    previous       INTEGER,           -- `accepted` before the change
    accepted       INTEGER,           -- and after it
    origin         TEXT NOT NULL,     -- as decision_origin above
    actor          TEXT,
    policy_version TEXT,
    created_at     TEXT NOT NULL
);

CREATE TABLE progress_events (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    job_id     TEXT NOT NULL,
    event_type TEXT NOT NULL,
    data       TEXT NOT NULL,
    created_at TEXT NOT NULL
);

-- One row per queue loop that runs now (ADR-0094 item 7), busy or idle: written
-- when the loop starts and every WORKER_HEARTBEAT_S, deleted when it stops
-- cleanly; a row silent for an hour is deleted by any loop that runs (a worker
-- that crashed).  GET /api/queue/status reads it.  Process state, not report
-- data: no key to jobs.
CREATE TABLE worker_heartbeats (
    worker_id      TEXT PRIMARY KEY,  -- host:pid:hex, as jobs.worker_id
    role           TEXT NOT NULL,     -- worker | all (the API process loop)
    max_concurrent INTEGER NOT NULL,  -- WORKER_MAX_CONCURRENT; 0 or less = no limit
    app_version    TEXT NOT NULL,     -- CTIParsor version (pipeline.__version__)
    started_at     TEXT NOT NULL,
    heartbeat_at   TEXT NOT NULL
);

-- Accounts (ADR-0097 items 14 and 15).  A local account carries an Argon2id
-- password_hash; an OIDC account carries an oidc_subject and no hash
-- (auth_source).  role is reader, analyst or admin (api/auth/permissions.py).
-- Process state, not report data: no key to jobs.
CREATE TABLE users (
    id            TEXT PRIMARY KEY,
    username      TEXT NOT NULL UNIQUE,
    display_name  TEXT NOT NULL DEFAULT '',
    auth_source   TEXT NOT NULL CHECK (auth_source IN ('local','oidc')),
    oidc_subject  TEXT UNIQUE,          -- '<iss>|<sub>' of an OIDC account
    password_hash TEXT,                 -- Argon2id; NULL for an OIDC account
    role          TEXT NOT NULL CHECK (role IN ('reader','analyst','admin')),
    disabled      INTEGER NOT NULL DEFAULT 0,
    created_at    TEXT NOT NULL,
    last_login_at TEXT
);

-- Web sessions, kept on the server (ADR-0097 item 14).  Keyed by the SHA-256
-- of the session id: the browser holds the id in the ctiparsor_session cookie,
-- and the id itself is never stored.
CREATE TABLE sessions (
    id_hash      TEXT PRIMARY KEY,
    user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    csrf_token   TEXT NOT NULL,
    created_at   TEXT NOT NULL,
    expires_at   TEXT NOT NULL,
    last_seen_at TEXT NOT NULL
);
CREATE INDEX idx_sessions_user ON sessions(user_id);

-- Bearer API tokens, `ctp_...` (ADR-0097 item 14).  Stored as the SHA-256 of
-- the token (api/auth/store.py, hash_secret).
CREATE TABLE api_tokens (
    id           TEXT PRIMARY KEY,
    user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name         TEXT NOT NULL,
    token_hash   TEXT NOT NULL UNIQUE,
    created_at   TEXT NOT NULL,
    expires_at   TEXT NOT NULL,
    revoked_at   TEXT,
    last_used_at TEXT
);
CREATE INDEX idx_api_tokens_user ON api_tokens(user_id);

-- One row per failed sign-in.  The sign-in lockout counts them here, so that
-- every process agrees (ADR-0097 item 14).
CREATE TABLE login_failures (
    username     TEXT NOT NULL,
    attempted_at TEXT NOT NULL
);
CREATE INDEX idx_login_failures_username ON login_failures(username, attempted_at);
CREATE INDEX idx_login_failures_attempted ON login_failures(attempted_at);

-- A sign-in with an identity provider that is under way (ADR-0097 item 14,
-- part B).  Keyed by the SHA-256 of the state, which travels in the URL.  A row
-- is read once, then deleted, and lives 10 minutes.  binding_hash is the
-- SHA-256 of a value that is also set as a cookie in the browser that started
-- the sign-in.
CREATE TABLE oidc_logins (
    state_hash    TEXT PRIMARY KEY,
    nonce         TEXT NOT NULL,
    code_verifier TEXT NOT NULL,
    next_path     TEXT NOT NULL,
    binding_hash  TEXT NOT NULL,
    created_at    TEXT NOT NULL,
    expires_at    TEXT NOT NULL
);
CREATE INDEX idx_oidc_logins_expires ON oidc_logins(expires_at);

-- The audit trail (ADR-0097 item 17): one row per state-changing request to
-- /api and per change made by `python -m api.admin` (api/audit.py).  No foreign
-- key to users: a record outlives the account it names.  at is fixed-width UTC
-- text, so the time order and the text order agree.  prune deletes by it,
-- after AUDIT_RETENTION_DAYS (default 365; 0 keeps every row).
CREATE TABLE audit_events (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    at         TEXT NOT NULL,
    request_id TEXT,
    user_id    TEXT,
    username   TEXT,
    role       TEXT,
    auth       TEXT NOT NULL CHECK (auth IN ('session','token','none','cli')),
    method     TEXT,
    route      TEXT NOT NULL,
    target     TEXT,                    -- JSON text of the path parameters, or of the
                                        -- account or token a command-line change named
    status     INTEGER,
    outcome    TEXT NOT NULL CHECK (outcome IN ('ok','refused','error')),
    client     TEXT,
    attempted  TEXT
);
CREATE INDEX idx_audit_events_at ON audit_events(at);
CREATE INDEX idx_audit_events_user ON audit_events(user_id);

-- The files of a deleted job that the filesystem refused to remove (#724), written in
-- the same transaction as the job's rows.  One row per file: its canonical path, under
-- uploads/, uploads/meta/ or output/.  No foreign key: the job's row is the thing deleted.
-- A row goes when its file is removed; attempts and last_error say what failed.
CREATE TABLE job_file_cleanups (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    job_id     TEXT NOT NULL,
    path       TEXT NOT NULL,
    attempts   INTEGER NOT NULL DEFAULT 0 CHECK (attempts >= 0),
    last_error TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (job_id, path)
);

CREATE TABLE relationship_policy (
    id          INTEGER PRIMARY KEY,  -- always 1 (singleton row)
    policy_json TEXT NOT NULL         -- serialised policy object
);

-- Stage 2f's CVE metadata, fetched from CIRCL when CVE_ENRICHMENT=true.  A row
-- with NULL description AND NULL cvss_score is a remembered miss, so an
-- unknown CVE is not looked up again on every run.  Only a definite answer is
-- remembered (CIRCL's 404, or a reply that is not a JSON object): a lookup that
-- fails (timeout, connection error, 5xx, unreadable body) saves nothing, and the
-- next run asks again.
CREATE TABLE cve_cache (
    cve_id      TEXT PRIMARY KEY,
    description TEXT,
    cvss_score  REAL,
    cvss_vector TEXT,
    fetched_at  TEXT NOT NULL
);

-- NER confidence cutoffs calibrated from analyst decisions (ADR-0051).  A row
-- overrides the stage default (GLINER_THRESHOLD, CyNER 0.70) for that one
-- source + entity type; no row = the default.  Written by
-- scripts/calibrate_thresholds.py --apply or POST /api/thresholds/recalibrate.
CREATE TABLE model_thresholds (
    source           TEXT NOT NULL,    -- cyner | gliner
    entity_type      TEXT NOT NULL,
    threshold        REAL NOT NULL,    -- discard below this raw score
    sample_size      INTEGER NOT NULL, -- decisions the fit was made on
    target_precision REAL,             -- what the cutoff was asked to reach
    precision_at     REAL,             -- empirical precision at the cutoff
    recall_retained  REAL,             -- share of accepted entities still shown
    origin           TEXT NOT NULL,    -- calibrated | manual
    updated_at       TEXT NOT NULL,
    PRIMARY KEY (source, entity_type)
);

-- Deny / promote lists grown from analyst decisions (ADR-0052).  Only rows
-- with status='active' act: a deny row drops the exact (value, entity_type)
-- from every NER stage's output, a promote row adds the term to the Stage 2b
-- gazetteer.  Written as candidates by scripts/promote_overrides.py --apply or
-- POST /api/overrides/promote; activated by a person.
CREATE TABLE entity_overrides (
    id             TEXT PRIMARY KEY,
    term           TEXT NOT NULL,      -- exact value, case-folded and trimmed
    entity_type    TEXT NOT NULL,
    action         TEXT NOT NULL,      -- deny | promote
    status         TEXT NOT NULL,      -- candidate | active | ignored
    display        TEXT,               -- most common surface form (the gazetteer canonical)
    accepted_count INTEGER NOT NULL,   -- the counts the rule was met with
    rejected_count INTEGER NOT NULL,
    job_count      INTEGER NOT NULL,   -- distinct reports behind them
    origin         TEXT NOT NULL,      -- auto | manual
    note           TEXT,
    created_at     TEXT NOT NULL,
    updated_at     TEXT NOT NULL,
    UNIQUE (term, entity_type, action)
);

-- Detection-rule store (ADR-0006) — corpus-derived, not per-job.
-- Built by scripts/build_detection_index.py from local Sigma clones.
CREATE TABLE detection_rules (
    id           TEXT PRIMARY KEY,    -- corpus:native_key
    corpus       TEXT NOT NULL,
    native_key   TEXT NOT NULL,       -- Sigma id / content hash (cross-corpus dedup)
    format       TEXT NOT NULL DEFAULT 'sigma',  -- sigma|suricata|yara (ADR-0015)
    title        TEXT NOT NULL,
    description  TEXT DEFAULT '',
    severity     TEXT, license TEXT, source_ref TEXT,
    content_hash TEXT, data_sources TEXT, raw TEXT,
    platform     TEXT DEFAULT '',     -- windows|linux|macos|'' from logsource (ADR-0014)
    dedup_key    TEXT DEFAULT '',     -- sha256 of normalized detection logic (ADR-0010)
    is_canonical INTEGER DEFAULT 1    -- 0 = duplicate folded by the dedup pass
);

-- Rule body sizes (ADR-0022) — a side table, deliberately NOT a column on
-- detection_rules: a column added after `raw` (a multi-kilobyte body) forces
-- a walk past it to read one integer on SQLite (8.2s for 10k rules vs
-- ~0.1s here, the original measurement this table's shape is based on;
-- unmeasured on PostgreSQL specifically, ADR-0053, but the side table costs
-- nothing extra either way). Written on ingest; backfill an older store with
-- scripts/backfill_rule_bytes.py.
CREATE TABLE rule_bytes (
    rule_id TEXT PRIMARY KEY,
    bytes   INTEGER NOT NULL DEFAULT 0
);

-- Declared provenance from a rule's `related:` block (ADR-0017) — lets dedup
-- fold renamed/derived copies that no content hash would catch.
CREATE TABLE rule_related (
    rule_id     TEXT NOT NULL,
    related_key TEXT NOT NULL,
    rel_type    TEXT NOT NULL,        -- derived|renamed|similar|obsolete|merged
    PRIMARY KEY (rule_id, related_key, rel_type)
);

-- Detection atoms (ADR-0014) — the literal values each rule looks for.
-- Built alongside detection_rules; backfillable via scripts/build_rule_atoms.py.
CREATE TABLE rule_atoms (
    rule_id    TEXT NOT NULL,
    atom_class TEXT NOT NULL,         -- image|cmdline|file|registry|hash|domain|ip|url|pipe|service|port|user
    value      TEXT NOT NULL,         -- normalized, indexed for observable lookup
    PRIMARY KEY (rule_id, atom_class, value)
);

CREATE TABLE rule_techniques (
    rule_id      TEXT NOT NULL,
    technique_id TEXT NOT NULL,       -- ATT&CK id, indexed for coverage lookup
    propagated   INTEGER NOT NULL DEFAULT 0,  -- 1: inherited from the cluster by dedup, recomputed each pass (#432); 0: its own tag
    PRIMARY KEY (rule_id, technique_id)
);

-- Where each figure landed in `report_text` (ADR-0032).  `char_start`/`char_end`
-- delimit its sentinel-wrapped block, so an entity can be traced back to the
-- figure it came from rather than to the page.
CREATE TABLE report_figures (
    id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    ordinal INTEGER NOT NULL,
    page INTEGER NOT NULL,
    bbox TEXT NOT NULL,
    kind TEXT NOT NULL,
    char_start INTEGER NOT NULL,
    char_end INTEGER NOT NULL,
    provider TEXT NOT NULL DEFAULT '',
    model TEXT NOT NULL DEFAULT '',
    sha256 TEXT NOT NULL DEFAULT '',
    UNIQUE (job_id, ordinal),
    FOREIGN KEY (job_id) REFERENCES jobs(id) ON DELETE CASCADE
);

-- The figure-read cache (ADR-0033), keyed on the crop bytes rather than on the
-- job: a re-run, or the same figure in another report, does not re-pay the model.
CREATE TABLE figure_reads (
    sha256 TEXT NOT NULL,
    model TEXT NOT NULL,
    prompt_version INTEGER NOT NULL,
    read_json TEXT NOT NULL,
    created_at TEXT NOT NULL,
    PRIMARY KEY (sha256, model, prompt_version)
);

-- Full-text index over rule title+description (ADR-0031), 0.4 ms instead of
-- 4.1 s.  Rebuilt with the rule store (rebuild_store, #363) and by
-- scripts/build_rule_text.py; brand evidence is
-- simply absent while the table is empty, exactly as proposals degrade while
-- the atom index is unbuilt.  No corpus re-clone.  A plain table since
-- ADR-0053, not a SQLite FTS5 virtual one: body_tsv is a GENERATED column,
-- so it can never drift out of sync with body the way a separately-built
-- FTS5 index could.
CREATE TABLE rule_text (
    rule_id  TEXT PRIMARY KEY REFERENCES detection_rules(id) ON DELETE CASCADE,
    body     TEXT NOT NULL,
    body_tsv tsvector GENERATED ALWAYS AS (to_tsvector('simple', body)) STORED
);
CREATE INDEX idx_rule_text_tsv ON rule_text USING GIN (body_tsv);
```
